# Commander combos

`#/combos` is linked alongside the homepage bulk count; the bulk label still opens `#/bulk`.

The daily 07:23 UTC Pages workflow refreshes the Scryfall commander query `(is:commander or (t:legendary t:background)) game:paper` and Commander Spellbook's official `https://json.commanderspellbook.com/variants.json.gz` export. Search pages are fetched serially with 550 ms spacing. Default-card bulk printings supply actual full-art, borderless, then extended-art images, with a complete normal-card fallback. Eligibility comes from Scryfall, including permitted noncreature commanders. Original paper release dates are computed across printings so a future reprint does not make an existing commander appear unreleased. Backgrounds are labeled pairing options and require a legal lead. Existing command-zone rules validate Partner, partner-with, Friends Forever, Background and Doctor choices.

The bulk reader scans individual JSON records because the decompressed source exceeds Node's single-string size limit. It retains concrete ingredients, quantities, zones, states, commander requirements, generic templates, outcomes, nullable counts, mana, prerequisites, steps, source categories and original combo links. Images missing from the source are resolved by Oracle identity from the existing static Scryfall catalog. No inventory or account data enters this pipeline.

The compressed commander catalog is content-addressed, checksum-verified, and loaded from a small manifest. Combo shards contain at most 40 lines, are also content-addressed and checksum-verified, and load only when a commander/page is opened. Every line explicitly contains a selected command-zone card; merely color-compatible combos are not offered. Pair selection deduplicates loaded lines. Each selected card's lines retain their source-independent heuristic ordering; combined pair results are not claimed to be one global power ordering.

Estimated strength sorts potential finishers before other infinite engines and other outcomes, then fewer pieces and less stated setup mana. These are transparent heuristics, not absolute power scores or deck power ratings. Source category labels remain separate. Infinite mana is not automatically a win. Commander/color legality and additional commander requirements are shown independently of ownership. Generic template requirements cannot be satisfied merely by owning every named card.

Bulk ownership sums quantities across printing/finish rows only when Oracle IDs match. It performs no saves, transfers or inventory writes. Unsupported identities safely appear missing. An owned label does not verify prerequisites or execution.

Refresh validates complete paging, dataset size, nonregressing source time, ingredient schema, identity membership and source collapse. It writes immutable shards first and swaps the manifest last. A source failure aborts the workflow and leaves the last deployed snapshot intact. The prior validated archive is restored and saved using Actions cache. Old shards remain available during a refresh for clients with an earlier manifest. The page exposes source update and generation timestamps and bounded coverage.

Attribution: [Commander Spellbook API guidance](https://spacecowmedia.github.io/commander-spellbook-backend/api.html) explicitly recommends this bulk export for third-party apps and requires credit. Each combo links back to Spellbook. Source-code MIT licensing is not asserted as ownership of all combo data or card art. Card images are complete Scryfall card images with artist/copyright information and a card-source link.

Validation: `node tests/regression/commander-combos.cjs`; browser suite `node tests/regression/commander-combos-ui.cjs` with `DECK_SAGE_PREVIEW_URL` pointing to an isolated preview. Browser accounts and all account RPCs are mocked; external writes are rejected. `DECK_SAGE_REAL_ART=true` permits real card-image GETs for visual inspection only. Test-only fixture descriptions are never published as source data.
